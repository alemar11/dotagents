# Codex Review Closeout

Load before the mandatory current-head Codex review gate. GitStack owns review
request, wait, warning, findings, reply, resolution, and provider reconciliation
contracts. Implement Feature supplies immutable repository, PR, head, base,
merge-base, and prior-evidence identity.

Journal every request, waiter, warning, reply, or resolution as a separate
one-use owner operation. Never retry ambiguous transport; reconcile the exact
target through GitStack/provider readback.

Request review for the current exact PR tuple. Reuse a result only when that
tuple is unchanged and every actionable finding is dispositioned. A changed
head, base, merge base, PR identity, material diff, repository rule, tracker
delivery, or relevant documentation invalidates affected evidence.

Use one immutable 45-minute deadline per request. Launching after expiry allows
one zero-timeout read. Pending at the deadline requires GitStack's persistent
warning for the same lineage before the result may continue as
`warned-timeout`. Never repost, extend the deadline, start a second waiter, or
call a timeout clean. A later merge workflow must recheck late findings.

Before terminal closeout, prove every PR is open, non-draft, conflict-free, and
current for mergeability, base freshness, approval, branch rules, and queue
eligibility. Unknown or pending blocks. Never enqueue or merge.

## Tracker Closeout

Place each hosted implementation issue's closing ref in its owning default-base
delivery PR. Add whole-Spec or accepted parent refs only after their complete
gates pass. Use fully qualified refs across repositories. Hosted issues remain
open until merge.

For local Markdown, perform the predeclared move only after substantive,
integration, and domain-closeout proof; commit and push it, then regenerate all
head-bound evidence. The result remains prepared closeout until merge.
