# Feature Contract Repair

Load the plugin contract at
[`../../../references/contract-repair.md`](../../../references/contract-repair.md)
when a separately invoked Feature task receives its exact portable request.
This is an internal `existing-source` branch, not a selectable option or a
third source route.

## Semantic Repair

Reread the complete linked Feature Spec set and complete durable issue graph.
Resolve every conflicting clause against current repository, test, runtime, and
contract evidence. Ask the originating root only for missing factual evidence;
that is clarification, not authorization. Block when the evidence cannot
support one unambiguous durable contract.

Apply the smallest complete repair, which may change one or more Specs, issues,
relationships, dependencies, acceptance clauses, validation obligations,
metadata, or `allowed_paths`. Create or supersede issues only when graph
correctness requires it. Preserve all current executor-owned checkbox markers,
progress, implementation notes, and evidence sections on retained artifacts.
Never infer implementation progress from stale request text.

After synthesis, rerun Spec hardening, acceptance coverage, issue-graph
completeness, dependency validity, overlap, verticality, readiness, and tracker
validation for the entire bundle. The result must be a complete executable
bundle, not merely a locally consistent changed artifact.

## Publication

Preview writes nothing and returns `proposed`. Publish rereads each target,
applies changes in dependency-safe order, verifies relationships and metadata,
appends the portable audit, and rereads the complete bundle. Follow
`references/publication.md` for fail-safe mutation and idempotent partial
recovery. Return only `applied`, `proposed`, `no-op`, or `blocked` using the
exact plugin-level result contract.

Before returning, validate the portable request, result, audit, preservation,
readback, and partial-operation consistency with the shipped plugin-level
stateless validator. Feature remains the semantic authority; validation does
not decide what the repaired contract should say.
